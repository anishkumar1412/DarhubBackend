Farmer Profile API Routes

Complete request, response, authentication, update, and error reference

Base path: /api/farmer | Route source: routes/farmerRoutes.js | Last verified: 2026-09-06

1. Overview

The farmer profile router exposes two routes. Both routes require the authenticated farmer's access token and resolve the farmer from the JWT subject. The profile tabs are selected with the tab query parameter.

Authentication: send Authorization: Bearer <access_token> on every request. The access token is verified with the backend JWT secret. Tokens are issued by the authentication flow and must not be hard-coded in the app.
MethodPathPurpose
GET/api/farmer/profileRead one profile view selected by tab.
PATCH/api/farmer/profileUpdate the personal profile view. Currently only tab=personal is supported.

3. GET Profile

GET/api/farmer/profile?tab={tab}

Returns the authenticated farmer's selected profile view.

Query parameterRequiredAllowed values
tabYesmain, personal, farm, address, bank

All successful GET responses use this envelope:

{
  "success": true,
  "data": { ... }
}

4. PATCH Profile

PATCH/api/farmer/profile?tab=personal

Partially updates the authenticated farmer's personal details and primary address.

Content type: application/json. The request body may include either object or both objects. Omitted properties are preserved.

{
  "personal_info": {
    "first_name": "Ramesh",
    "last_name": "Yadav",
    "mobile_number": "9876543210",
    "email": "ramesh@example.com",
    "dob": "1990-05-12",
    "profile_image": "https://example.com/profile.jpg"
  },
  "address_details": {
    "lane_1": "Main Road",
    "lane_2": "Near Market",
    "state": 1,
    "district": 5,
    "block": 12,
    "village": "Gondal",
    "pincode": "360311"
  }
}
Body objectSupported fieldsBehavior
personal_infofirst_name, last_name, mobile_number, email, dob, profile_imageUpdates User for mobile/email and UserProfile for the remaining supported fields.
address_detailslane_1, lane_2, state, district, block, village, pincodeUpdates the existing primary address, or creates one with is_primary: true when none exists.

Successful response:

{
  "success": true,
  "message": "Personal profile updated successfully"
}

Current limitation: the PATCH handler does not update gender, marital status, education, occupation, bank details, UPI details, farm records, or non-primary addresses. PATCH requests using any tab other than personal return HTTP 400.

5. Integration Checklist

  • Store the access token securely and attach it as a Bearer token.
  • Send one of the five supported GET tab values exactly as documented.
  • Handle address_details: null and empty arrays without assuming records exist.
  • Display total_acres as a string for now; do not assume it is a numeric field.
  • Mask account numbers in the UI and avoid logging bank responses.
  • For profile edits, send only the fields being changed and use tab=personal.
  • After a successful PATCH, refresh the personal tab because the update response is message-only.
