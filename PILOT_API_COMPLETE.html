1. Authentication and route matrix

+

Authenticated routes use Authorization: Bearer <access_token>. Generic authentication validates the JWT; strict pilot authentication also reloads the user and requires user_type === 3.

+
Security note: several legacy pilot work routes currently have no authentication middleware: order listing, order detail, start day, update work, image upload, end day, and comments. This reflects the live implementation and should be reviewed before production exposure.

2. Registration

+

POST /api/user/pilot-registration uses multipart/form-data. Required: first_name, last_name, email, password, mobile_number. At least one verification flag must be true. Optional: DOB, Aadhar, PAN, UPI, role, JSON address, and JSON bank details.

+

Files: profile_image (JPG/JPEG/PNG); identity/certification fields (JPG/JPEG/PNG/PDF); passbook_image (JPG/JPEG/PNG). Each file is limited to 5 MB and each field accepts up to five files.

+
address=[{"state":"1","district":"2","block":"3","lane1":"Road 1","village":"Aji","pincode":"360003","is_primary":true}]
bank_details=[{"bank_name":"SBI","acc_holder_name":"Ramesh","acc_number":"12345","ifsc_code":"SBIN0001","is_primary":true}]
+
{"success":true,"message":"Pilot registered successfully","user_id":123,"token":"<access_token>"}
+

Common errors: 400 validation/duplicate data, 401 invalid optional creator token, 500 registration failure.

3. Profile

+

GET /api/user/pilot/profile?tab={main|personal|address|bank|documents} returns {success:true,data:{...}}. Main contains user info and assigned/active order counts. Personal contains identity, DOB, Aadhar, PAN, image, and primary address. Address returns all addresses. Bank returns bank and UPI arrays. Documents returns active uploaded document metadata.

+

PUT /api/user/pilot-edit accepts multipart data and updates profile, address, bank, UPI, and documents. It updates the logged-in user by default; another user_id requires admin authorization. Supplied address/bank sets replace existing records.

+

4. Work execution

+

Orders and assignment

GET /api/pilot/work/orders/:pilot_user_id returns {success,orders}, including dates, acreage, price, status, address, log counts, and drone ID. An unassigned ID returns 200 with an empty array.

+

POST /api/pilot/work/confirm-assignment requires strict pilot auth:

{"booking_id":123,"accepted_dates":["2026-09-07","2026-09-08"]}
+

Daily work

POST /api/pilot/work/start-day requires booking_id, pilot_user_id, and working_date; optional fields are copilot and drone. It returns 201 for a new log and 200 for an existing log.

{"booking_id":123,"pilot_user_id":45,"co_pilot_user_id":46,"drone_id":7,"working_date":"2026-09-07"}

POST /api/pilot/work/update-work requires booking and date, and accepts completed acres, fertilizer, pesticide, water, notes, start time, and end time. The daily log must exist. POST /api/pilot/work/end-day uses the same core body. POST /api/pilot/work/add-comment requires booking, pilot, and comment. POST /api/pilot/work/upload-field-image/:log_id accepts land_image, JPG/JPEG/PNG.

5. Maintenance

Maintenance routes use generic Bearer auth. POST /api/pilot/maintenance submits immediately; POST /api/pilot/maintenance/draft saves a draft. Both accept JSON or multipart and require drone_id.

{"drone_id":7,"maintenance_type":"Scheduled Maintenance","task_name":"Routine Inspection","scheduled_date":"2026-09-07","actual_date":"2026-09-07","engineer_id":12,"overall_status":"Good","checklist":[{"component":"Propellers","expected_status":"Good","actual_status":"Good","remarks":"No cracks"}]}

If no checklist is supplied, the default eight-component checklist is created. Health scores are Good/Updated 100, Wear & Tear 70, Damaged 30, Needs Replacement 0, averaged across items.

GET /stats returns totals and health statistics. GET / supports search, form_status, overall_status, maintenance_type, page, and limit. GET /:id returns task/checklist/attachments. PUT /:id updates drafts. PATCH /:id/submit submits a draft with an overall status. DELETE /:id soft-deletes. Attachment routes add or remove files.
